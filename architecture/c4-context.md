# C4 Model — Уровень контекста (System Context)

## Описание системы

**StayService** — это веб-приложение для автоматизации дополнительных услуг гостиничного комплекса. Система предоставляет гостям единый цифровой интерфейс для бронирования услуг, заказа еды и вызова персонала, а администраторам и персоналу — инструменты для управления сервисами и задачами.

## Внешние акторы

### 1. Гость гостиницы
Основной пользователь системы. Взаимодействует с системой через веб-браузер (адаптивный интерфейс для мобильных устройств). Использует систему для:
- Бронирования допуслуг (баня, СПА, лежаки, столики)
- Заказа еды в номер
- Вызова персонала
- Записи на мероприятия
- Просмотра расписания активностей

### 2. Администратор гостиницы
Управляет системой через веб-интерфейс админ-панели. Отвечает за:
- Настройку услуг, цен и временных слотов
- Управление бронированиями и заказами
- Назначение персонала на заявки
- Формирование отчётов
- Экстренную связь с гостями

### 3. Персонал (горничные, повара, аниматоры, техники)
Используют мобильный интерфейс системы для получения и выполнения задач:
- Получение уведомлений о новых заявках
- Обновление статусов задач
- Подтверждение выполнения услуг

## Внешние системы

### 1. Система бронирования гостиницы (Hotel Booking System)
Основное ПО гостиницы, которое управляет номерным фондом и заселением гостей.

**Тип интеграции:** REST API (синхронный вызов)

**Что происходит:** При заселении гостя система бронирования автоматически передаёт в StayService данные гостя:
- Номер бронирования
- Одноразовый код доступа
- Номер комнаты
- ФИО гостя
- Даты заезда и выезда

**Надёжность:** Реализована идемпотентность — повторная отправка с тем же номером бронирования обновит запись, а не создаст дубликат. При ошибке система бронирования повторит отправку.

### 2. Сервис уведомлений (Notification Service)
Внешний сервис для отправки push-уведомлений и email гостям и персоналу.

**Тип интеграции:** REST API / SMTP

**Использование:**
- Уведомления о подтверждении бронирования
- Уведомления о статусе заказа еды
- Уведомления о выполнении заявок персонала
- Экстренные уведомления от администратора

## Описание потоков данных

1. **Гость → StayService:** Запросы на бронирование, заказ еды, вызов персонала через HTTPS
2. **StayService → Гость:** Подтверждения, уведомления, данные меню и расписания
3. **Администратор → StayService:** Управление услугами, ценами, персоналом через HTTPS
4. **Персонал → StayService:** Обновление статусов задач через мобильный интерфейс
5. **Система бронирования → StayService:** Передача данных гостя при заселении через REST API
6. **StayService → Сервис уведомлений:** Отправка push/email уведомлений
