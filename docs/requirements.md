# Требования к системе StayService

## 1. Функциональные требования

### 1.1 Модуль аутентификации и авторизации

| ID | Требование | Приоритет |
|----|-----------|-----------|
| FR-1.1.1 | Система должна предоставлять гостю возможность авторизации по номеру бронирования для доступа к бронированию допуслуг до заселения | M |
| FR-1.1.2 | Система должна предоставлять гостю возможность авторизации по номеру бронирования и одноразовому коду для полного доступа после заселения | M |
| FR-1.1.3 | Система должна автоматически завершать сессию через 24 часа после последней активности | S |
| FR-1.1.4 | Система должна принимать данные гостя от основного ПО гостиницы через REST API при заселении | M |

### 1.2 Модуль бронирования услуг

| ID | Требование | Приоритет |
|----|-----------|-----------|
| FR-1.2.1 | Система должна отображать список доступных услуг: баня, СПА, лежаки у бассейна, лежаки на пляже, столики в ресторане | M |
| FR-1.2.2 | Система должна отображать календарь с цветовой индикацией доступности слотов (свободно: зелёный, занято: серый) | M |
| FR-1.2.3 | Система должна проверять доступность слота и создавать запись в БД при бронировании | M |
| FR-1.2.4 | Система должна позволять гостю просматривать и отменять свои активные бронирования в личном кабинете | M |

### 1.3 Модуль заказа еды

| ID | Требование | Приоритет |
|----|-----------|-----------|
| FR-1.3.1 | Система должна отображать полное меню ресторана с категориями, фотографиями, описаниями и ценами | M |
| FR-1.3.2 | Система должна позволять гостю добавлять блюда в корзину, указывать количество и комментарии | M |
| FR-1.3.3 | Система должна создавать заказ со статусом "новый" и отправлять уведомление на кухню | M |
| FR-1.3.4 | Система должна позволять гостю просматривать историю своих заказов в личном кабинете | S |

### 1.4 Модуль вызова персонала

| ID | Требование | Приоритет |
|----|-----------|-----------|
| FR-1.4.1 | Система должна отображать кнопку "Вызвать персонал" на главном экране | M |
| FR-1.4.2 | Система должна отображать список типов запросов: "Горничная", "Техническая проблема", "Дополнительные полотенца", "Другое" | M |
| FR-1.4.3 | Система должна автоматически определять номер комнаты из профиля гостя и создавать заявку | M |
| FR-1.4.4 | Система должна позволять гостю просматривать статус своих заявок ("новая", "в обработке", "выполнено") | S |

### 1.5 Модуль записи на мероприятия

| ID | Требование | Приоритет |
|----|-----------|-----------|
| FR-1.5.1 | Система должна отображать расписание мероприятий на текущую неделю | M |
| FR-1.5.2 | Для каждого мероприятия система должна отображать: название, описание, дату/время, лимит участников, количество свободных мест | M |
| FR-1.5.3 | Система должна проверять наличие свободных мест и создавать запись при записи на мероприятие | M |
| FR-1.5.4 | Система должна позволять гостю отменять запись на мероприятие с освобождением места | S |

### 1.6 Модуль админ-панели

| ID | Требование | Приоритет |
|----|-----------|-----------|
| FR-1.6.1 | Система должна предоставлять администратору доступ к панели управления с разделами: "Услуги", "Бронирования", "Заказы", "Персонал", "Отчёты" | M |
| FR-1.6.2 | Администратор должен иметь возможность добавлять/редактировать/удалять услуги, устанавливать цены, настраивать временные слоты | M |
| FR-1.6.3 | Администратор должен видеть список всех активных бронирований с возможностью отмены или изменения | M |
| FR-1.6.4 | Система должна генерировать отчёты: загрузка услуг по дням, выручка от допуслуг, популярные блюда | C (Could have) |

### 1.7 Модуль доступа для персонала

| ID | Требование | Приоритет |
|----|-----------|-----------|
| FR-1.7.1 | Система должна предоставлять персоналу доступ к мобильному интерфейсу с авторизацией по логину и паролю | M |
| FR-1.7.2 | Система должна отображать сотруднику список его активных задач с указанием приоритета и статуса | M |
| FR-1.7.3 | Система должна позволять сотруднику изменять статус задачи ("новая" → "в работе" → "выполнена") | M |
| FR-1.7.4 | Система должна отправлять уведомление сотруднику о новой задаче | M |

## 2. Нефункциональные требования

### 2.1 Производительность

| ID | Требование | Целевое значение |
|----|-----------|------------------|
| NFR-2.1.1 | Время отклика системы на действия пользователя | ≤ 2 секунды |
| NFR-2.1.2 | Поддержка одновременной работы пользователей | ≥ 500 пользователей |
| NFR-2.1.3 | Время загрузки главного экрана приложения | ≤ 3 секунды |

### 2.2 Надёжность и доступность

| ID | Требование | Целевое значение |
|----|-----------|------------------|
| NFR-2.2.1 | Доступность системы | ≥ 99% времени в месяц |
| NFR-2.2.2 | Максимальное время восстановления после сбоя | ≤ 30 минут |

### 2.3 Безопасность

| ID | Требование | Целевое значение |
|----|-----------|------------------|
| NFR-2.3.1 | Хранение персональных данных гостей | В зашифрованном виде |
| NFR-2.3.2 | Одноразовый код доступа | Действителен только в течение текущего проживания |
| NFR-2.3.3 | Логирование действий пользователей | Все действия для аудита |

### 2.4 Удобство использования

| ID | Требование | Целевое значение |
|----|-----------|------------------|
| NFR-2.4.1 | Доступность основных функций | Не более 3 кликов от главного экрана |
| NFR-2.4.2 | Обращения к персоналу по вопросам использования | ≤ 10% от общего числа гостей |

### 2.5 Совместимость

| ID | Требование | Целевое значение |
|----|-----------|------------------|
| NFR-2.5.1 | Поддержка браузеров | Chrome, Safari, Firefox, Yandex (последние 2 версии) |
| NFR-2.5.2 | Работа с корпоративным Wi-Fi гостиницы | Корректная работа |

### 2.6 Масштабируемость

| ID | Требование | Целевое значение |
|----|-----------|------------------|
| NFR-2.6.1 | Увеличение количества пользователей | До 800 пользователей |
| NFR-2.6.2 | Хранение данных | Не менее 3 лет |
